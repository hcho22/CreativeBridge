**Learnings for future iterations:**
- **Cosine similarity formula breakdown**: Breaking calculation into clear steps (dot product, magnitude A, magnitude B, division) improves readability and debugging. Each step can be validated independently.
- **Edge case defense is critical**: Zero vectors (magnitude = 0) and dimension mismatches are common in production - explicit handling prevents downstream crashes. Return 0.0 for zero vectors (mathematically undefined but sensible default).
- **Floating-point precision**: Cosine similarity should always be in [-1, 1] range, but floating-point arithmetic can produce 1.0000000000000002. Always clamp results to prevent assertion failures.
- **Helper functions enable practical use**: While calculateCosineSimilarity is the core, real use cases need findMostSimilarVector (find best match from candidates), batchCalculateSimilarity (process multiple comparisons), areSimilar (threshold-based matching with default 0.75).
- **Test with known vector pairs**: Mathematical guarantees (identical=1.0, orthogonal=0.0, opposite=-1.0) validate algorithm correctness better than random tests.
- **Performance scales linearly**: Batch processing 1000 1536-dimensional vectors completes in < 1 second, confirming algorithm is efficient enough for real-time diversity checking.
- **Magnitude invariance**: Cosine similarity measures direction, not magnitude - vectors [1,1,1] and [2,2,2] have similarity 1.0. This is ideal for embeddings where magnitude doesn't carry semantic meaning.

**Technical decisions:**
- Separate loops for dot product and magnitudes: More readable than combined loop, minimal performance impact
- Explicit error throwing for invalid inputs: Empty vectors and dimension mismatches should fail fast rather than return incorrect results
- Warning for zero vectors instead of error: Zero vectors are edge case but not necessarily an error - log warning and return 0.0
- Clamping to [-1, 1]: Handle floating-point precision errors gracefully rather than returning values like 1.0000000000000002
- Helper function for threshold checking: areSimilar(v1, v2, 0.75) is more readable than calculateCosineSimilarity(v1, v2) >= 0.75
- Batch function returns 0.0 for invalid vectors: Allows partial processing of mixed valid/invalid batches without failing entire operation

**Similarity detection insights:**
- **Threshold semantics**: 1.0 = exact match (identical embeddings), 0.75 = high similarity (synonyms, close concepts), 0.5 = moderate similarity (related concepts), <0.3 = weak/no similarity.

- **False positive tradeoff**: High threshold (0.9) misses semantic similarities (dragon vs wyrm). Low threshold (0.5) flags unrelated elements. 0.75 balances well for story elements.
- **Cross-type similarity use cases**: "crystal cave" (setting) might be similar to "magic crystal" (object). Current implementation supports this via includeAllTypes flag.
